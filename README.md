# FileTransferApp

Windows에서 같은 LAN의 PC끼리 파일과 텍스트를 주고받는 프로그램입니다. C++20, Win32 표준 컨트롤, Winsock을 사용합니다.

일반 사용자는 **FileTransferAppGui.exe**를 실행하세요. **FileTransferApp.exe**는 콘솔 사용·진단·자동 테스트용입니다. 두 프로그램의 기본 연결 방식과 수신 저장 위치가 다르므로 아래 사용 순서를 확인하세요.

## 주요 기능

| 기능 | 설명 |
|---|---|
| LAN 기기 발견 | 같은 앱이 실행 중인 기기를 목록으로 표시하고 새로고침할 수 있습니다. |
| 사용자 승인 연결 | 상대를 선택해 연결을 요청하면 상대가 승인해야 메시지·파일 기능이 활성화됩니다. |
| 직접 IP 연결 | 발견 목록에 나오지 않는 상대에게 IPv4와 실제 TCP 포트로 연결을 요청합니다. |
| 양방향 메시지 | 연결된 양쪽에서 Unicode 텍스트를 전송합니다. 전송 버튼과 Enter를 지원합니다. |
| 파일 전송 | 파일 선택 대화상자 또는 파일 하나의 드래그 앤 드롭으로 전송할 파일을 선택합니다. |
| 별도 파일 수신 승인 | 연결 승인 이후에도 파일마다 수신자가 파일명·크기를 확인하고 승인 또는 거절합니다. |
| 진행 상태·취소 | 송신·수신 진행률과 상태를 표시하며 각 방향을 별도로 취소할 수 있습니다. |
| 대용량 스트리밍 | 고정 크기 버퍼로 처리합니다. 프로토콜상 파일 크기 상한은 1 TiB이며 모든 크기를 실측한 것은 아닙니다. |
| 저장·무결성 확인 | SHA-256 검증과 저장 완료 ACK를 사용합니다. 기존 파일을 덮어쓰지 않습니다. |
| 이어받기·완료 조회 | 기존 전송 ID와 원본 파일로 중단된 전송을 복구하거나 이전 완료 결과를 확인합니다. |
| 저장 폴더 설정 | GUI 수신 폴더를 변경하고 다음 실행에도 유지합니다. |
| Win32 GUI | 창 크기·DPI에 맞춰 배치하고 작은 높이에서는 세로 스크롤을 제공합니다. |

계정, 클라우드 저장소, 인터넷 원격 연결, NAT traversal, TLS 암호화, 영속적인 GUI 전송 이력은 포함하지 않습니다. 연결 승인은 강한 신원 인증을 대신하지 않습니다.

## 1. 준비 및 빌드

### 개발 환경

- Windows 및 Visual Studio 2026 Community
- **Desktop development with C++** 워크로드, MSVC v145, Windows SDK
- C++20 지원

외부 GUI 프레임워크는 필요하지 않습니다. 저장소를 받은 뒤 루트의 `FileTransferApp.slnx`를 여세요.

### Visual Studio에서 실행

1. 솔루션 구성을 **Debug 또는 Release**, 플랫폼을 **x64**로 선택합니다.
2. `FileTransferAppGui`를 시작 프로젝트로 지정합니다.
3. 솔루션을 빌드합니다.
4. Visual Studio에서 실행하거나 아래 출력 경로의 GUI 실행 파일을 실행합니다.

### 명령줄에서 빌드

Visual Studio Developer PowerShell을 열고 저장소 루트에서 실행합니다.

```powershell
msbuild FileTransferApp.slnx /m /p:Configuration=Debug /p:Platform=x64
msbuild FileTransferApp.slnx /m /p:Configuration=Release /p:Platform=x64

& ./FileTransferApp/x64/Release/FileTransferAppGui.exe
```

| 프로그램 | Debug 출력 | Release 출력 |
|---|---|---|
| GUI | `FileTransferApp/x64/Debug/FileTransferAppGui.exe` | `FileTransferApp/x64/Release/FileTransferAppGui.exe` |
| CLI | `x64/Debug/FileTransferApp.exe` | `x64/Release/FileTransferApp.exe` |

GUI는 인자 없이 실행하면 창을 엽니다. CLI는 인자 없이 실행하면 Host/Connect 콘솔 메뉴를 표시합니다. 실행 예시는 모두 저장소 루트를 기준으로 합니다.

## 2. 두 PC에서 연결하기

### 권장: LAN 기기 목록 사용

1. 두 PC를 같은 LAN에 연결하고 **양쪽에서 GUI를 실행**합니다.
2. 창 상단의 **LAN 기기** 목록에 상대가 나타나는지 확인합니다. 필요하면 **새로고침**을 누릅니다.
3. 상대의 컴퓨터 이름과 IPv4 주소를 확인하고 목록에서 선택합니다. 표시 이름과 ID는 미인증 정보입니다.
4. **선택 기기 연결 요청**을 누릅니다.
5. 상대 PC에서 연결 요청에 표시된 IP와 이름을 확인한 뒤 **연결 승인**을 누릅니다. 원하지 않는 요청은 **연결 거절**을 누릅니다.
6. 양쪽 연결 상태가 연결 완료로 바뀌고 메시지·파일 버튼이 활성화되는지 확인합니다.

목록에 나타나는 것만으로 자동 연결되지 않습니다. 연결 및 승인 대기는 전체 15초 제한이 있으므로 만료되면 다시 요청하세요. 한 앱은 한 상대와 연결하며, 연결 중 다른 기기를 사용하려면 먼저 **연결 해제**를 누릅니다.

### 상대가 목록에 없을 때: 직접 IP 연결

1. 상대 PC에서 `ipconfig`로 LAN 어댑터의 IPv4 주소를 확인합니다.
2. 상대 GUI의 LAN 상태에서 **실제 TCP 수신 포트**를 확인합니다.
3. 요청하는 PC의 IPv4/포트 입력란에 **상대 PC의 주소와 포트**를 입력합니다.
4. **IP 직접 연결 요청**을 누릅니다.
5. 상대 PC에서 **연결 승인**을 누르고 연결 완료를 확인합니다.

두 PC 사이에서는 `127.0.0.1`을 사용하지 않습니다. 이 주소는 자기 PC를 가리키며 같은 PC에서 여러 인스턴스를 시험할 때 사용합니다.

기본 수신 포트는 TCP **9000**입니다. 사용 중이면 OS가 고른 임시 포트로 대체될 수 있으므로 직접 연결할 때는 항상 상대 GUI에 표시된 실제 포트를 사용하세요. 직접 IP 연결도 사용자 승인이 필요합니다.

### 연결 해제·재연결

**연결 해제**는 활성 연결 또는 승인 대기 요청을 정리합니다. 기본 GUI에서 다시 연결하려면 목록 선택 또는 직접 IP 요청을 반복하고 상대 승인을 다시 받아야 합니다.

## 3. 메시지 보내기

1. 상대와 연결을 완료합니다.
2. 메시지 영역의 입력창에 내용을 입력합니다.
3. **메시지 전송** 또는 **Enter**를 누릅니다.
4. 상대의 메시지 기록에서 수신 내용을 확인합니다.

연결된 양쪽 모두 전송할 수 있습니다. 메시지 기록에는 연결·파일 작업의 상태와 오류도 표시됩니다.

## 4. 파일 보내고 받기

### 보내는 PC

1. 상대와 연결을 완료합니다.
2. **파일 선택**에서 파일 하나를 선택하거나 탐색기에서 파일 하나를 GUI 창에 놓습니다.
3. 선택된 파일 정보를 확인합니다. 선택만으로 전송되지는 않습니다.
4. **파일 보내기**를 누릅니다.
5. 받는 사람이 파일 요청을 승인할 때까지 기다립니다.
6. 송신 진행 상태를 확인합니다. 필요하면 **송신 취소**를 누릅니다.
7. 저장 완료 ACK가 확인된 최종 성공 상태를 확인합니다.

### 받는 PC

1. 파일 전송 영역에 표시된 **다운로드 폴더**를 확인합니다. 다른 위치를 쓰려면 승인 전에 **폴더 변경**으로 선택합니다.
2. 수신 요청의 파일명과 크기를 확인합니다.
3. **승인** 또는 **거절**을 누릅니다. 상단의 연결 승인과는 별도의 파일 수신 승인입니다.
4. 수신 진행 상태를 확인합니다. 필요하면 **수신 취소**를 누릅니다.
5. 저장·해시 검증 완료 상태를 확인한 뒤 다운로드 폴더에서 파일을 확인합니다.

진행률 **100%만으로 송신 성공을 판단하지 마세요.** 데이터 전송 이후 상대의 저장·검증 결과를 확인해야 합니다. 실패나 취소 상태에서는 메시지 기록을 확인하세요. 기존 파일은 덮어쓰지 않으며 폴더 단위 전송은 제공하지 않습니다.

## 5. 다운로드 폴더 설정

GUI는 최초 실행 시 Windows의 **Downloads 폴더**를 사용합니다. 파일 전송 영역의 **폴더 변경**으로 바꿀 수 있습니다.

- 설정 파일: `%LOCALAPPDATA%\FileTransferApp\download-folder.txt`
- 선택한 폴더는 재실행 후에도 유지됩니다.
- 폴더 선택 취소 또는 검증·설정 저장 실패 시 기존 설정을 유지합니다.
- 폴더 오류는 메시지 기록에 표시됩니다. 유효한 폴더를 선택하기 전에는 수신 승인을 할 수 없습니다.
- 승인 시 해당 요청의 저장 위치가 확정됩니다. 전송 도중 폴더를 바꾸면 다음 승인부터 적용됩니다.
- 수신 요청마다 별도 저장 대화상자를 띄우는 방식은 아닙니다. 승인 전에 기본 폴더를 변경하세요.

**CLI는 현재 작업 디렉터리의 `received/`에 저장합니다.** GUI의 Downloads 설정을 사용하지 않습니다. 복구할 때는 원래 사용한 프로그램과 수신 폴더를 확인하세요.

## 6. 중단된 전송 이어받기·완료 조회

전송 ID는 새 전송 때 GUI에 표시됩니다. 나중에 복구하려면 **전송 ID를 별도로 보관**하세요. GUI의 전체 전송 이력이 재실행 후 복원되는 기능은 없습니다.

1. 양쪽 앱에서 다시 연결 요청·승인을 완료합니다.
2. 수신자는 **원래 전송을 승인했던 수신 폴더**를 선택합니다.
3. 송신자는 **내용이 변경되지 않은 원본 파일**을 다시 선택합니다.
4. 송신자는 기존 **전송 ID**를 입력합니다.
5. 중단된 전송을 계속하려면 **이어받기**, 이미 저장되었는지 확인하려면 **완료 조회**를 누릅니다.
6. 수신 요청이 표시되면 수신자가 내용을 확인하고 승인합니다.
7. 최종 저장·검증 결과를 확인합니다.

같은 원본과 복구 메타데이터, 원래 수신 위치가 필요합니다. 원본 변경·ID 불일치·검증 실패는 거부됩니다. 새 GUI 복구 정보는 수신 디렉터리 ID에도 묶여 있어 파일과 메타데이터를 다른 폴더로 옮겨 복구할 수 없습니다. 이전 버전의 복구 정보는 기존 파일 ID 검증을 유지합니다. 복구를 계획한다면 남은 부분 파일과 메타데이터를 임의로 삭제하거나 이동하지 마세요.

## 7. 네트워크와 실행 설정

### 포트·발견 범위

| 용도 | 설정 |
|---|---|
| LAN 발견 | IPv4 UDP multicast `239.255.90.8:9001`, TTL 1 |
| GUI 연결 승인 및 전송 | 기본 TCP 9000, 바인드 실패 시 임시 포트 대체 가능 |
| 직접 연결 입력란 | 상대방의 IPv4와 실제 TCP 포트 |
| CLI 기본 포트 | TCP 9000 |

방화벽·공유기 client isolation·VPN·다중 NIC·서브넷 구분 등에 따라 발견 또는 연결이 제한될 수 있습니다. UDP 발견이 실패해도 TCP 직접 연결은 사용할 수 있습니다. 네트워크 어댑터 구성이 바뀌면 앱을 재실행하세요.

Windows 방화벽에서 앱의 실제 TCP 포트와 UDP 9001 multicast 송수신 허용이 필요할 수 있습니다. 회사 장비에서는 관리자에게 승인된 네트워크 범위의 규칙을 요청하세요. 앱과 테스트는 방화벽, Smart App Control, 보안 정책을 변경하거나 우회하지 않습니다.

컴퓨터 이름과 앱의 존재는 활성 IPv4 네트워크에 광고될 수 있으며, 가입 가능한 VPN·가상 NIC도 포함될 수 있습니다. 메시지·파일 통신에는 TLS 암호화나 강한 상대 인증이 없으므로 상대 IP와 요청을 확인하세요.

### 환경 변수

| 변수 | 의미 |
|---|---|
| `FILETRANSFER_LAN_PORT` | GUI 수신 포트 지정, 0~65535. 0이면 OS 선택. 지정 포트도 바인드 실패 시 임시 포트로 대체될 수 있습니다. |
| `FILETRANSFER_GUI_SETTINGS` | GUI 다운로드 설정 **파일**의 절대경로. 수신 폴더 자체를 지정하는 변수가 아닙니다. |

현재 PowerShell 세션에서 실행할 앱에만 설정하는 예:

```powershell
$env:FILETRANSFER_LAN_PORT = '0'
$env:FILETRANSFER_GUI_SETTINGS = Join-Path $env:TEMP 'FileTransferApp-demo/download-folder.txt'
& ./FileTransferApp/x64/Release/FileTransferAppGui.exe

# 이후 실행부터 기본 설정을 사용하려면 환경 변수 제거
Remove-Item Env:FILETRANSFER_LAN_PORT
Remove-Item Env:FILETRANSFER_GUI_SETTINGS
```

환경 변수를 제거해도 저장된 설정 파일이나 받은 파일은 삭제되지 않습니다.

## 8. CLI 및 GUI 호환 모드

기본 GUI는 파일 프로토콜 전에 **연결 승인 greeting**을 사용합니다. CLI는 파일 프로토콜 **6**만 사용하므로 기본 GUI와 직접 연결되지 않습니다. 승인 없는 연결 방식으로 자동 전환하지 않습니다.

CLI끼리 사용하려면 두 터미널 또는 두 PC에서 실행합니다.

```powershell
# 받는 쪽 / Host
& ./x64/Release/FileTransferApp.exe --host --port 9000

# 연결하는 쪽: 아래 예시 주소를 실제 Host의 IPv4로 교체
& ./x64/Release/FileTransferApp.exe --connect 192.168.0.10 --port 9000

# 도움말과 프로토콜 버전
& ./x64/Release/FileTransferApp.exe --help
& ./x64/Release/FileTransferApp.exe --version
```

| 연결 후 CLI 입력 | 동작 |
|---|---|
| 일반 텍스트 | 상대에게 메시지 전송 |
| `/file <path>` | 파일 전송 요청 |
| `/accept` | 수신 파일 승인 |
| `/reject` | 수신 파일 거절 |
| `/cancel [requestId]` | 전송 취소, 필요하면 요청 ID 지정 |
| `/resume <transferId> <path>` | 기존 전송 이어받기 |
| `/status <transferId> <path>` | 기존 저장 완료 결과 확인 |
| `/reconnect` | 같은 상대 주소로 재연결 |
| `/quit` | 종료 |

Host는 `--bind IPv4`로 바인드 주소를 지정할 수 있고 Host/Connect 모두 `--reconnect` 옵션을 지원합니다. CLI 수신 위치는 실행 파일 위치가 아닌 **현재 작업 디렉터리의 `received/`**입니다.

CLI와 GUI의 상호 운용 또는 기존 진단이 필요하면 GUI를 명시적으로 호환 모드로 실행합니다.

```powershell
& ./FileTransferApp/x64/Release/FileTransferAppGui.exe --legacy-cli
```

이 모드에서는 이전 수동 Host/Client 화면을 사용합니다. 한쪽에서 **연결 대기**, 다른 쪽에서 IP·포트를 입력하고 **연결**을 누릅니다. 새 LAN 발견·연결 승인 게이트는 사용하지 않습니다. 기본 GUI끼리 쓰려면 양쪽 모두 인자 없이 실행하세요.

## 9. 문제 해결

| 증상 | 확인할 사항 |
|---|---|
| 상대가 기기 목록에 없음 | 상대 앱 실행, 같은 LAN, 새로고침, multicast 제한 확인. 실제 IPv4·포트로 직접 연결을 시도합니다. |
| 직접 연결 실패 | 상대 GUI에 표시된 실제 포트, 상대 LAN IPv4, 방화벽, 승인 대기 만료를 확인합니다. |
| 메시지·파일 버튼 비활성 | 연결 승인 완료 여부를 확인합니다. 파일 보내기는 파일 선택·검증도 완료되어야 합니다. |
| 수신 승인 불가 | 유효한 다운로드 폴더와 연결 상태, 현재 요청 여부를 확인합니다. |
| 파일이 예상 위치에 없음 | GUI는 선택한 다운로드 폴더, CLI는 작업 디렉터리의 received입니다. 최종 저장 완료 상태도 확인합니다. |
| 이어받기·완료 조회 거부 | 기존 전송 ID, 변경되지 않은 원본, 원래 수신 폴더와 복구 메타데이터를 확인합니다. |
| 작은 창에서 아래 버튼이 안 보임 | 오른쪽 세로 스크롤바나 마우스 휠로 진행 상태·이어받기 영역으로 이동합니다. |
| 기본 GUI와 CLI가 연결되지 않음 | 연결 승인 greeting 차이입니다. CLI 상호 운용은 명시적 GUI 호환 모드를 사용합니다. |
| 실행이 보안 정책에 의해 차단됨 | 표시된 차단 정보를 확인하고 관리자에게 문의합니다. 정책 해제나 우회 실행은 하지 않습니다. |

## 10. 검증 결과와 알려진 제한

최종 코드의 Debug/Release x64 빌드와 자동 검증 기록은 [GUI 스크롤 수정 기록](tests/GUI_SCROLL_FIX.md)에 있습니다.

| 검사 | Debug | Release |
|---|---:|---:|
| CLI stage1~5 회귀 | 121 | 121 |
| Unicode 회귀 | 43 | 43 |
| 기존 GUI 기본·고급·다운로드 | 35 | 35 |
| LAN GUI | 25 | 25 |
| 신규 스크롤 검사 | 32 | 32 |
| 합계 | 256 | 256 |

기존 **448개**와 신규 **64개**, 총 **512개 PASS**입니다. 이 수치는 이전 코드 검증 결과이며 README 문서 편집 자체를 대상으로 테스트를 다시 실행한 수치는 아닙니다.

스크롤 수정은 컨트롤 이동 후 이전·새 영역의 부모 배경, 자식 컨트롤, 테두리를 함께 갱신합니다. 더블 버퍼링은 추가하지 않았습니다. 정지 후 픽셀 비교는 통과했지만, 원본에서도 보고된 지속 잔상을 재현하지 못했으므로 실제 사용자 환경의 완전 해결을 확정하지 않습니다.

아직 필요한 수동 검증:

- 실제 두 PC의 LAN/Wi-Fi 발견·연결·파일 전송
- 빠른 휠·실제 스크롤바 드래그, 스크롤 중 크기 변경, 다른 창으로 가린 뒤 표시하는 상황의 육안 잔상 확인
- 100%, 125%, 150% DPI와 모니터 이동 시 배치·화면 확인
- 실제 IME 조합 및 탐색기 드래그 앤 드롭

주요 재검증 명령:

```powershell
# 기본 GUI의 LAN 발견·연결 승인·파일 전송
powershell -NoProfile -ExecutionPolicy RemoteSigned -File tests/stage8_lan.ps1 -Exe FileTransferApp/x64/Release/FileTransferAppGui.exe

# 기본/호환 모드의 스크롤 범위·좌표·정지 후 픽셀 비교
powershell -NoProfile -ExecutionPolicy RemoteSigned -File tests/gui_scroll.ps1 -Exe FileTransferApp/x64/Release/FileTransferAppGui.exe
```

전체 448개 회귀의 빌드·실행 순서는 [STAGE8 재검증 명령](tests/STAGE8.md#재검증-명령)을 참고하세요. 스크롤 검사를 추가하면 총 512개입니다. GUI 자동화는 대화형 데스크톱에서 순차 실행하고 다른 창 조작을 피하세요. 테스트 결과·파일·이미지는 `tests/runs/`에 격리되며 Git에서 제외합니다.
