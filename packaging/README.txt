FileTransferApp v{{VERSION}} — Windows x64 사용자 안내

1. 설치와 실행

배포 후보 대상: Windows 10 1703 이상 / Windows 11 x64.
모든 OS 빌드·보안 정책 조합을 검증한 것은 아닙니다. 지원되는 최신 Windows 사용을 권장합니다.
Visual Studio와 Git은 필요하지 않습니다. 앱용 별도 설치 프로그램은 없습니다.

GitHub Releases의 FileTransferApp-v{{VERSION}}-win-x64.zip을 다운로드하고
Windows 탐색기에서 '모두 압축 풀기'를 선택하세요. ZIP 안에서 직접 실행하지 말고
압축을 푼 폴더의 FileTransferAppGui.exe를 실행하세요.
저장소가 Private이면 접근 권한이 있는 계정만 다운로드할 수 있습니다.

이 앱은 Microsoft Visual C++ v14 x64 런타임이 필요합니다.
공식 최신 x64 Visual C++ Redistributable을 설치하세요.
https://aka.ms/vc14/vc_redist.x64.exe
공식 안내: https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist
빌드에 사용한 MSVC 도구보다 같거나 새로운 런타임이 필요합니다.
MSVCP140.dll, MSVCP140_ATOMIC_WAIT.dll, VCRUNTIME140.dll,
VCRUNTIME140_1.dll 오류가 나면 공식 런타임 설치/업데이트를 확인하세요.
개별 DLL을 비공식 사이트에서 내려받지 마세요. Windows 시스템 DLL과 VC++ DLL은 ZIP에 포함하지 않습니다.

2. 상대와 연결하기

양쪽 PC를 같은 LAN에 연결하고 앱을 실행하세요.
LAN 기기 목록에서 상대의 이름과 IPv4를 확인하고 선택한 뒤
'선택 기기 연결 요청'을 누르세요. 상대가 '연결 승인'을 눌러야 연결됩니다.
연결을 승인하면 상대가 보내는 파일을 지정된 다운로드 폴더로 자동 수신합니다.
원하지 않는 요청은 '연결 거절'을 누르세요. 검색만으로 자동 연결되지 않습니다.

상대가 보이지 않으면 새로고침하거나 직접 IP 연결을 사용하세요.
상대 PC의 ipconfig에서 LAN IPv4를 확인하고 상대 GUI의 LAN 상태에서
실제 TCP 포트를 확인하세요. 요청하는 PC에 상대 IPv4/포트를 입력하고
'IP 직접 연결 요청'을 누른 뒤 상대가 승인합니다.
다른 PC에 연결할 때 127.0.0.1은 사용하지 마세요. 자기 PC 주소입니다.

기본 TCP 수신 포트는 9000이며 사용 중이면 임시 포트로 바뀔 수 있습니다.
항상 상대 GUI에 표시된 실제 포트를 사용하세요. 연결·승인 대기는 15초 후 만료될 수 있습니다.
연결을 끝내려면 '연결 해제'를 누르세요. 재연결 시 다시 요청·승인이 필요합니다.

3. 메시지와 파일 보내기

메인 창의 '대화 창 열기'를 누르고 별도 창에서 메시지를 입력하세요.
Enter는 전송, Shift+Enter는 줄바꿈입니다. 대화 창을 닫아도 연결과 파일 전송은 유지됩니다.
창은 이동·크기 조절·최대화할 수 있고 재열기 시 기록과 초안이 유지됩니다.
파일은 '파일 선택'에서 하나를 고르거나 탐색기의 파일 하나를 앱 창에 놓습니다.
선택 정보를 확인하고 '파일 보내기'를 누르세요.
받는 PC는 지정된 다운로드 폴더에서 파일명·크기·저장 가능 여부를 자동 검증하고 수신합니다.
기본 GUI에는 파일별 승인/거절 절차가 없습니다. 원하지 않는 상대는 연결을 승인하지 마세요.

각 방향의 진행률과 상태를 확인하고 필요하면 '송신 취소'/'수신 취소'를 누르세요.
100%만으로 송신 성공을 판단하지 마세요. 저장 완료 ACK·SHA-256 검증 결과까지 확인하세요.
기존 파일은 덮어쓰지 않으며 폴더 단위 전송은 제공하지 않습니다.

4. 파일 저장 위치

GUI 최초 수신 위치는 Windows Downloads 폴더입니다.
'폴더 변경'으로 바꾸면 다음 실행에도 유지됩니다.
설정 파일: %LOCALAPPDATA%\FileTransferApp\download-folder.txt
폴더에 문제가 있으면 자동 수신을 거부합니다. 유효한 폴더를 선택하세요.
수신 준비 시 저장 위치가 확정되므로 전송 중 변경은 다음 수신 준비부터 적용됩니다.
앱 폴더 삭제만으로 받은 파일이나 사용자 설정이 삭제되지는 않습니다.

5. 이어받기·완료 조회

새 전송에 표시되는 전송 ID를 별도로 보관하세요.
다시 연결·승인한 뒤 수신자는 원래 저장 폴더를 선택하고,
송신자는 변경되지 않은 원본 파일을 선택해 기존 ID를 입력하세요.
'이어받기' 또는 '완료 조회'를 누르면 수신자가 자동으로 복구 정보를 검증합니다.
같은 원본·복구 메타데이터·원래 수신 폴더가 필요합니다.
부분 파일과 복구 정보를 임의로 삭제하거나 다른 폴더로 옮기지 마세요.
완료 시 저장 ACK와 SHA-256 검증 결과를 확인합니다.

6. 네트워크·방화벽 점검

LAN 발견: IPv4 UDP multicast 239.255.90.8:9001, TTL 1.
연결·전송: 상대 앱에 표시된 실제 TCP 수신 포트.
Windows Defender Firewall 허용이 필요하면 신뢰할 수 있는 Private 네트워크에서
이 앱/필요한 포트에 한정해 허용하세요. 회사 PC는 관리자에게 문의하세요.
방화벽 전체나 SmartScreen/Smart App Control을 끄지 마세요.

공유기 client isolation, VPN, 다른 서브넷, multicast 제한은 발견을 막을 수 있습니다.
UDP 발견 실패 시에도 TCP 직접 IP 연결을 시도할 수 있습니다.
네트워크 어댑터 구성이 바뀌면 앱을 재실행하세요.
컴퓨터 이름·앱 존재가 VPN을 포함한 활성 IPv4 네트워크에 광고될 수 있습니다.
표시 이름과 ID는 인증된 신원이 아니며 연결 동의는 강한 인증·암호화가 아닙니다.
TLS·인터넷 원격 연결·계정 기능은 제공하지 않습니다.

7. 보안·검증 제한

이 후보 EXE는 코드 서명되지 않았습니다. SmartScreen/SAC/회사 정책이 실행을 막을 수 있습니다.
SHA-256 체크섬은 파일 일치 확인용이며 코드 서명이나 게시자 인증을 대신하지 않습니다.
차단 시 오류 정보를 확인하고 관리자/제작자에게 문의하세요. 정책을 우회하지 마세요.
모든 Windows PC에서 실행된다고 보장하지 않습니다.

기존 v1.0.0의 실제 두 PC LAN 연결·전송 성공은 사용자가 확인했습니다.
이번 대화 창·자동 수신 수정본의 실제 두 PC 검증은 별도로 필요합니다.
스크롤 잔상, 실제 마우스 드래그, 100/125/150% DPI, IME와 탐색기 drop은
환경별 수동 검증이 필요합니다. 작은 창에서는 세로 스크롤로 아래 버튼을 찾으세요.
