# 1단계 검증

이 문서는 1단계 당시의 기록입니다. 이후 변경과 현재 검증 결과는 [2단계 결과](STAGE2.md)를 참고하세요.

Visual Studio Community 2026, C++20, v145, Windows Winsock2에서 검증했습니다.
프로젝트의 기존 빌드 설정은 변경하지 않았습니다.

## 실행

프로젝트 루트에서 x64 Debug 또는 Release를 빌드한 후 실행합니다.
포트 9000이 비어 있어야 하며 테스트를 동시에 실행하지 마세요.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests/stage1.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tests/stage1.ps1 -Exe FileTransferApp/x64/Release/FileTransferApp.exe
```

테스트는 실제 exe 두 개 또는 exe와 .NET TCP 상대방을 연결합니다.
각 실행의 파일과 로그는 `tests/runs/<임의 ID>/`에 보존합니다.
기존 `received` 폴더는 사용하지 않습니다. 테스트가 만든 프로세스만 정리합니다.

1. 유휴 상태를 거친 후 localhost 양방향 텍스트
2. 파일 승인, 저장, 기존 ACK 수신, SHA-256 일치
3. 파일 요청 거절
4. 양쪽 동시 파일 요청 및 승인 대기 중 양쪽 `/quit`
5. 로컬 `/quit`으로 승인 대기 취소 및 종료, 3초 이내
6. 상대방 정상 종료로 승인 대기 취소, 3초 이내
7. 상대방 TCP reset으로 승인 대기 취소, 3초 이내
8. 잘못된 메시지 타입으로 연결 중단 및 승인 대기 취소, 3초 이내
9. 상대방이 읽지 않아 정체된 파일 송신 중 `/quit`, 3초 이내 종료
10. 정체된 송신의 소켓 타임아웃 및 연결 중단
11. 승인된 파일 수신 도중 상대방 종료 시 `.part` 즉시 정리
12. 분할 프레임 및 한 번에 이어진 두 프레임 처리, 유휴 수신 중 종료

## 종료 설계

- `RequestStop()`은 종료 상태를 기록하고 `shutdown()`과 승인 대기 취소를 수행합니다.
- `SessionCleanup`은 정상 종료와 예외 경로 모두에서 종료 요청 → 송신/수신 join → `Disconnect()` 순서를 보장합니다.
- 실제 `closesocket()`은 송수신 I/O가 끝난 뒤 수행합니다. 소켓 핸들 및 종료 상태는 mutex로 보호합니다.
- `ReceiveLoop()`의 정상 EOF, 소켓 오류, 프로토콜 오류, 예외 모두 같은 종료 경로를 거칩니다.
- 승인 취소 상태는 연결 수명 동안 유지하여 뒤늦게 시작된 송신 작업이 취소를 지우지 못하게 합니다.
- 수신은 250ms마다 종료 상태를 확인합니다. 정상 유휴 연결은 유지됩니다.
- 송신 호출은 2초 타임아웃을 사용합니다. 실패 시 스트림 상태를 보존할 수 없으므로 연결을 중단합니다. Windows의 타임아웃 오차를 고려해 종료 테스트는 3초를 허용합니다.

처음에는 `shutdown()`만 사용했지만 상대방이 연결을 유지하는 테스트에서 수신 join이 끝나지 않았습니다.
소켓 타임아웃을 추가한 후 해당 테스트와 정체된 송신 테스트가 통과했습니다.
리다이렉트된 출력에서 승인 대기 문구가 버퍼에 남는 문제는 명시적 flush로 수정했습니다.
수신 시작 출력 대신 실제 `.part` 존재 여부로 수신 중단 테스트를 동기화합니다.

## 범위와 남은 작업

이번 단계는 연결된 세션의 종료와 수명 관리에 한정합니다.
연결 준비(`Initialize`, `StartServer`, `Connect`)는 작업 스레드 시작 전에 수행하며,
`Network` 객체의 소멸 전에는 객체를 사용하는 모든 스레드를 join해야 합니다.
`SessionCleanup`이 현재 콘솔 프로그램에서 이 조건을 보장합니다.

상대방이 종료되어도 콘솔의 `getline()`은 입력을 기다립니다. 작업 스레드와 승인은
해제되며 `/quit` 또는 입력 EOF로 프로세스를 종료할 수 있습니다.
접속 전 `accept()`/`connect()` 취소, 실제 두 노트북 LAN/Wi-Fi 테스트, 스레드 생성 실패의
강제 주입 테스트는 수행하지 않았습니다. 2초 송신 타임아웃은 실제 네트워크 환경에서 조정할 수 있습니다.

승인 검사 전 파일 생성 문제는 2단계에서 수정해야 합니다.
requestId, 상태 머신, ACK를 기다린 후 송신 성공 반환은 3단계 작업으로 남아 있습니다.
이번 SHA-256 테스트는 저장된 파일을 외부에서 비교하며, 프로토콜 내부 해시 검증은 구현하지 않았습니다.
